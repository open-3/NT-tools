# Agent Pulse

并发 Agent 状态浮窗。把 Codex、DeepSeek Harness、WorkBuddy 三个工具里
**正在跑的**和**跑完你还没看的**对话，收在一个始终浮在桌面上的小窗里。

解决一个问题：你同时开着好几个 agent 干活，切来切去看谁在等我 ——
现在抬眼就能看到。

---

## 一、会话列表

只显示三种状态，其余一律不显示；全空闲时列表为空，2 秒后自动收成细条。

| 状态 | 意思 |
|---|---|
| **待确认**（琥珀） | agent 卡在等你授权或回答 |
| **进行中**（绿） | 正在干活 |
| **完成未读**（蓝） | 跑完了，结果你还没看 |

**排序**：待确认 → 进行中 → 完成未读；同级按**等得最久**排前面。
刚启动 3 秒的新会话，不会把等了两小时的待确认挤下去。

### 每条卡片显示什么

```
[C] 转换                      sam…local    39m
    ● 已调整为至少保留两个 end。· ⎇ feature-a   8 文件
```

| 位置 | 内容 |
|---|---|
| 标题 | 会话标题 + **项目名**（压缩到 20 字符）+ 时长 |
| 第二行 | 状态点 + **结果摘要** / 当前动作 / 等待原因 |
| 第二行尾 | **git 分支** + **改动文件数**（仅 Codex 能统计） |

- **结果摘要**：完成项直接显示它最后给了什么，不用点开（限 40 字符）
- **项目名**：`acme-service…backend-local` 这种压缩形式，否则标题被挤没
- **分支**：`main`/`master` 不显示（每个仓库都有，零信息量）

到代码没坏就先不看 —— 这是这个浮窗的核心假设。

## 二、状态感知（会主动变色）

不是新通知，是让**已经显示的那行字**在关键时刻变色。

| 功能 | 触发 | 表现 |
|---|---|---|
| **停滞感知** | 进行中 > 10 分钟无活动 | 琥珀 + `已停 X 分钟` |
| **卡住升级** | > 60 分钟无活动 | `可能卡住 · 已停 X 分钟` |
| **进度感知** | 进行中 | 显示 `第 N 轮`，判断还要等多久 |
| **过期预警** | 完成未读快滚出 2 小时窗口 | `还剩 X 分钟` |

为什么需要：一个 turn 实测能跑 12 小时，**「跑很久」和「卡死」从外面看一模一样**，
唯一信号是"多久没有活动了"。

> 完成未读只保留 2 小时。超时后结果就翻不回来了（日志还在，但你不会再想起来去翻）。

---

## 三、完成项折叠

完成未读超过 3 条时，自动收成一行「N 项已完成未读 · 展开」，
别把真正要处理的事挤出视野。点开仍能看到全部。

---

## 四、底栏

```
Alt Shift A 显隐            5h 82%        ● 2 等我 ● 1 在跑 ● 5 完成
```

- **负载总览**：彩色圆点 + 数字，比纯文字快
- **额度告警**：Codex 额度接近上限才出现（5h ≥75% / 7d ≥70%），平时完全不存在

## 五、工具箱

标题栏「工具」按钮打开，每个工具是独立窗口、**可多开**。

### JSON 格式化

- **行号栏折叠**：`{` `[` 行上有折叠箭头，点一下收起整个对象；行号会跳号（3 → 7）
- **语法高亮**：key 深蓝、字符串暗红、数字绿、`true/false/null` 蓝（VS Code 浅色配色）
- **一键格式化**：粘贴 → 点「格式化」→ 2 空格缩进，自动滚回顶部
- **打开 / 保存 / 另存为**：原生文件对话框
- **快捷键**：`Ctrl+S` 保存、`Ctrl+Shift+S` 另存、`Ctrl+O` 打开、`Ctrl+Shift+F` 格式化

> 折叠只是视图。保存的永远是完整内容，不会存成折叠后的残缺 JSON。
> 折叠状态下编辑区只读（避免误改），展开即可编辑。

### 翻译

内嵌百度翻译页面，可正常输入翻译。

- **重载**：重新加载
- **首页**：回到百度翻译首页
- **外部打开**：用系统浏览器打开当前页

### 图片取字（OCR）

从截图/照片里提取文字，**完全本地识别，不联网**。

- **三种载入方式**：选择图片 / 拖拽 / 直接 `Ctrl+V` 粘贴
- 识别结果可直接编辑、一键复制
- 内置中英文语言包（4.46MB），离线可用
- 首次识别约 2 秒初始化，之后单张 0.9~2.7 秒

精度参考：白底正常字号约 **89%**，数字和英文准确；小字/复杂背景/彩色截图约 74%。

## 八、数据来源与只读原则

| 工具 | 数据源 | 「待确认」精确度 |
|---|---|---|
| Codex | `~/.codex` 的 sqlite + rollout 文件 | 推断（长时间无输出） |
| DeepSeek Harness | `~/.dsh` 的 projcache + 事件流 | **精确**（审批事件差集） |
| WorkBuddy | `~/.workbuddy*/workbuddy.db` | **精确**（状态机 `pending`） |

**所有数据只读**。sqlite 全部以 `readOnly` 打开，不写任何 agent 的数据。
已读/忽略状态存在自己的 `%APPDATA%/agent-pulse/state.json`。

### 三工具的显示能力不对等（数据决定的）

| | Codex | DSH | WorkBuddy |
|---|---|---|---|
| 结果摘要 | ✅ | ✅ | ❌ 正文在云端 |
| 改动文件数 | ✅ | ❌ | ❌ |
| 进度（第 N 轮） | ✅ | ✅ | ⚠️ 降级为「处理中」 |
| git 分支 | ✅ | ❌ | ❌ |

取不到就不显示，不估算、不假装。

## 九、已知限制

1. **Codex 的「待确认」是推断的**。它的日志里没有审批事件，只能用「
   inProgress + 60 秒无文件增长」推断，UI 上用空心点降透明度弱化显示。
2. **WorkBuddy 无法显示「在做什么工具」**。它的表只有会话级状态，
   没有细粒度动作记录。
3. **不做跳转**。点击卡片只标记已读，不会激活其他应用窗口。
4. **不做 token 用量统计**。自算的数字和本机 magpie 网关对不上，
   网关能截到每一条请求，而从 session 文件重建的总有漏 —— 已下架。
   额度百分比是服务端下发的，不受影响，保留。
5. **贴桌面 / 点击穿透未实现**。当前只有「置顶 / 不置顶」两档。
6. **列表超过 11 条要内部滚动**。日常负载很少超过 6 条，没做分页。

## 十、运行

```bash
cd app
npm install
npm start      # 构建 + 启动
npm test       # 跑单测
npm run dist   # 打包免安装 exe
```

打包产物：`release/AgentPulse-*-portable.exe`（约 100MB，免安装）。

首次启动后浮窗出现在主屏右侧偏上，托盘图标在通知区域。
检测不到的工具不显示，也不报错。
